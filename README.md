# 饶信谱脉 · 家谱数字化

上饶市广信区（原上饶县）各家族的老家谱数字化。微信小程序 + FastAPI 后端。

核心机制是**接力修谱**：一人建树 → 邀请码发到家族群 → 每人只填自己那一格 → 系统自动合并。

## 起步

### 1. 数据库

本机已装 MySQL 8.0.46，`backend/.env` 已配好（用户 `buddy`，库 `raoxin_genealogy`）。

换机器时复制 `.env.example` 为 `.env` 再改：

```ini
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=你的用户
DB_PASSWORD=你的密码
DB_NAME=raoxin_genealogy
DB_CHARSET=utf8mb4
WX_MOCK_LOGIN=true
```

> 建库不需要手工执行 SQL：`init_db.py` 会 `CREATE DATABASE IF NOT EXISTS`
> 并按 `utf8mb4_0900_ai_ci` 建库（与 DDL 里的排序规则一致）。

### 2. 建表 + 灌演示数据

```bash
cd backend
.venv/Scripts/python.exe scripts/init_db.py      # 15 张表
.venv/Scripts/python.exe scripts/seed_demo.py    # 广信陈氏演示数据
.venv/Scripts/python.exe scripts/check_schema.py # 核对模型与库是否对齐
```

`seed_demo.py` 会打印可用的浏览码和一条待补全示例。它是**可反复执行**的：
每次先清空再重灌，并把各表自增重置回 1，所以 `family_id` 永远是 1，
文档和编译模式里写死的 id 不会漂。

> **已经灌过数据的库不要跑 `init_db.py`**——它按 `schema.sql` 建表，等于重建。
> 加表/改列走增量脚本，一份一个文件、可重复执行：
>
> ```bash
> # 本地
> mysql -u buddy -p raoxin_genealogy < sql/migrate_2026-10-17_user_family.sql
> # 线上（会先自动 mysqldump 备份，再执行）
> backend/.venv/Scripts/python.exe _deploy/migrate.py backend/sql/migrate_2026-10-17_user_family.sql
> ```

### 3. 启动后端

```bash
cd backend
.venv/Scripts/python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

接口文档：http://127.0.0.1:8000/docs

### 4. 打开小程序

用微信开发者工具**导入** `miniprogram` 目录（不是整个仓库）。

所以图里没问题、端上基本就没问题。它还会顺手体检：悬空边、孤立点、
坐标 NaN、世次错行、脱敏口径，右侧另附一份**人物清单**便于逐条核对。改完布局算法后跑一次，比翻 JSON 快得多。

> 脱敏是**服务端按访问者身份算的**，改前端没用。所以要真名只能换身份：
> `--as=<账号名>` 会先用 `dev:<账号名>` 登录再请求（需要 `WX_MOCK_LOGIN=true`）。
>
> **姓名脱敏的分界线是「有没有认领」**（2026-10-16 口径，见
> `backend/docs/01-数据库设计.md` 4.2 节）：认领过的普通族人就能看到全族真名，
> 不必借管理员的身份；未认领的账号仍脱敏，脚本会提示。
> 产物按身份命名，凡含真名的（`tree-overview-full.html`、`tree-overview-<账号>.html`）
> **别提交、别外发**（`_verify/` 已在 `.gitignore`）。
>
> 小程序端同理：把 `utils/auth.js` 的 `DEV_IDENTITY` 改成一个**已认领**的身份
> 就能看到全名（比如 `'dev:mock_new_member'`——它在 seed 里已认领陈雨欣）。

`smoke_e2e.py` 用 ASGI 传输直接打应用（不起网络服务），覆盖 9 段 138 项断言：
游客视角、脱敏、我的一家、配某氏补全、两条写入路径、权限边界、配偶挂载回归、
答题自证。最后一段自建一组夹具（一位空着名字的母亲）验证「回答本身产生数据」，
跑完会自行拆掉，不去蹭别段的状态。

**它不幂等**：脚本会真的改数据（给「配某氏」填上名字、给陈国华配一位配偶、
改陈启华的职业），所以连跑第二次必然失败。脚本开头有前置自检，数据不是
「刚灌完」的状态会直接拒绝运行并告诉你先干嘛：

```
数据不是「刚灌完」的状态，本次冒烟无法开始。
  - 人物数 20，期望 19（多出来的是上次运行新增的人物）
  - 找不到姓名为空的人物（配某氏）——上次运行已经把名字补上了
  - 陈国华名下已有 1 段婚姻——「配偶不能挂成子女」这段回归没有可测的场景了
请先复原数据，再跑本脚本：
    .venv/Scripts/python.exe scripts/seed_demo.py
```

没有这道自检时，第二次运行只会吐出「❌ 种子数据里存在无名者」这类失败，
看起来像种子脚本坏了，很容易把排查方向带偏。

但它还有个盲区：**它验证的是磁盘上的代码，不是跑着的服务**。uvicorn 不带
`--reload` 启动后，磁盘上代码改了、`smoke_e2e.py` 全绿，而对外服务的仍是旧代码。
`check_live.py` 就是对真实端口做这件事，只在服务起着时有意义，所以两个都要跑。

> 踩过一次真实的坑：`w`/`h` 的修复在源码里、冒烟也过，但线上响应里根本没有
> 这两个字段——前端拿到 `undefined`，所有连线消失、锚点偏位，而 HTTP 是 200，
> 表面看像前端 bug。原因就是服务进程起在修复之前且没开热重载。

> 更隐蔽的一次：加了 `--reload` 之后 WatchFiles 的监听线程**静默死掉**——
> 日志里既没有报错、也不再打印 `Reloading`，进程活着、HTTP 200、旧路由照样应答。
> 源码层面完全看不出来。所以 `check_live.py` 现在会拿运行中服务的 `/openapi.json`
> 与磁盘源码导入出的路由表**逐条比对**，报出"源码有、服务没有"的每一条。

> 所以启动后端请带上 `--reload`（见上面的启动命令）。即便如此，
> **改完代码仍然值得看一眼 `check_live.py`** —— 热重载本身也会失灵。

### 进开发者工具之前，先跑前端预检

`tools/preflight-frontend.js` 做的事：**用小程序自己的代码，跑真实后端数据**。

可行性来自一个代码结构上的事实——`miniprogram/utils/tree-lines.js` 和 `format.js`
是纯函数，不碰 `wx.*`，所以能在 Node 里直接 `require`。于是"页面为什么空白"
被拆成三个可以分别验证的问题：

| 层 | 问什么 |
|---|---|
| 接口路径 | 前端调的 12 条 URL，后端都注册了吗 |
| 字段 | 前端要读的字段，响应里真的有吗 |
| 计算 | 拿到真实数据后，`buildLines()` 算出的样式里有没有 `NaN` |

第三层最值钱：它验证的是**前端自己的渲染逻辑**，不是我们对前端的猜测。
节点缺 `w`/`h` 时不会抛异常，只会静默算出 `NaN`，然后所有连线整体消失。

```
结果：50 项全部通过 —— 前端逻辑层与后端契约一致
下一步：在开发者工具里只剩样式和交互，不会再遇到空白/NaN。
```

> 注意：这个脚本自己也会写错。第一次跑它报了「用户未认领」，看着像前端的 bug，
> 实际是断言写成了 `personId`，而后端字段叫 `claimedPersonId`（前端读的是对的）。
> 所以它报"字段缺失"时，先去后端源码搜一下这个名字。

### 域名 / HTTPS 这件事为什么绕不开

微信对小程序 `request` 域名的硬性要求是 **HTTPS + 已备案域名 + 不带端口**，
而且域名要**在小程序后台的「request 合法域名」里登记**。少任何一条，真机就报
`request:fail url not in domain list`。

> 早期用 `http://IP` 时踩过这个坑：开发者工具的「不校验合法域名」**只对工具
> 自己生效**，手机上照拦不误——症状是"工具里接口正常、扫码预览接口不通"。
> 当时在手机上「打开调试」能绕过去，但那只是临时手段，体验版和正式版都用不了。
> 现在域名与证书都已就位，**开发者工具和真机走同一条路**，不会再有这种落差。

> ⚠️ 域名、DNS、备案、服务器是**四件独立的事**：`wangqiming.top` 在**阿里云**
> 注册、DNS 也在阿里云、备案做在**腾讯云**、服务器也是腾讯云。只要
> 「备案接入商 = 服务器厂商」就不需要额外动作；不等的话得先做「新增接入备案」，
> 否则云厂商会在网络层拦掉 80/443。

域名启用步骤（A 记录、443 放行、certbot 签发与续期）见
**`_deploy/README.md` 第四节的「启用域名 + HTTPS」**。

登录这段**已经不再依赖 mock**：`LOGIN_MODE` 只在连本机后端时用固定 code，
连云端一律走真 `wx.login()`。也就是说云端没有 Secret 时登录会失败——
这是刻意的：宁可跑不通，也不在线上留一个 `dev:` 后门。

## 演示身份与口令

开发期后端开着 `WX_MOCK_LOGIN=true`，此时小程序端可以用固定身份登录，
省掉"每次 `wx.login` 换一个人"的麻烦。

**规则只有一条：`LOGIN_MODE` 看的是「连哪个后端」，不是「在哪个环境」。**

| `utils/env.js` 的 `BACKEND` | 登录方式 | 结果 |
|---|---|---|
| `'local'`（本机后端，mock 开着） | 固定 code `dev:mock_xxx` | 可任意切演示账号 |
| `'cloud'` / `'cloudIp'`（云端，mock 已关） | 真 `wx.login()` | 每台微信一个独立用户 |

> 为什么不按 `envVersion` 分流：**真机调试的 `envVersion` 也是 `develop`**，
> 但它连的是云端。给它开小灶，就等于把「工具里通、体验版不通」那个落差再造一遍。
> 而 `dev:` 身份本来也只被本机后端接受，发到云端只会换来 `40029 invalid code`。
>
> 代价：连云端时开发者自己也是一个真实用户，不再能切到陈启明/陈雨欣。
> 想看演示账号就把 `BACKEND` 切回 `'local'`。

| 用途 | 改 `utils/env.js` 的 `DEV_IDENTITY` | 能做什么 |

## 接口契约要点

统一响应体 `{"code": int, "msg": str, "data": any}`，`code == 0` 为成功。
错误码表见 `docs/02-接口定义.md` 第 0.3 节。

### 树的节点与边（端上渲染的唯一依据）

```jsonc
// 节点：x/y 是左上角坐标，端上直接 left/top 定位
{ "id": 12, "x": 44, "y": 460, "gen": 4, "w": 88, "h": 96,
  "gender": 1, "role": 1, "living": 1,
  "name": "陈启明", "displayName": "陈启明",
  "isSelf": true, "onPath": true, "isPending": false }

// 边：只给 from/to，坐标由端上从 nodes 里查
{ "from": 7, "to": 15, "type": 1 }

// canvas：尺寸与间距，端上据此算缩放
{ "width": 592, "height": 736, "nodeWidth": 88, "nodeHeight": 96,
  "genGap": 140, "siblingGap": 20, "spouseGap": 12,
  "minGeneration": 1, "maxGeneration": 5 }
```

要点：

- **`w` / `h` 一定要有**。端上 `utils/tree-lines.js` 用它们算连线端点、
  `home.js` 的 `centerOn` 用它们把锚点滚到屏幕中间。丢了不会报错，
  只会让端上算出 `NaN` —— 线画不出来、锚点不居中，且看起来像前端 bug。
- `role` 是 `LineageRole`：1 承袭男 / 2 承袭女 / 3 配偶入 / 4 配偶出 / 5 外姓后代。
  **外孙（5）只出现在 `view=mine`，不出现在 `view=overview`**（产品决策第 2 条）。
- `isSelf` 仅对锚点本人为 true。`onPath` 标出从始祖到锚点的路径。

### 两种邀请码存在两个地方

| 码 | 存哪 |
|---|---|
| 族级浏览码（type=1） | `family.view_code` 字段，一族一个 |
| 编辑码（type=2） | `invite_code` 表，一人一张 |

对外只有一个入口，所以**所有"按码取邀请"都必须走 `services/invite_service.load_invite()`**。
绕过去直接 `select(InviteCode)` 的话，族浏览码会表现为「链接已失效」——
而它恰恰是家族群里传播最广的那个码。

### 无参数的写操作也要传 body

FastAPI 会把无默认值的 Pydantic body 参数视为必填，**即使模型里没有必填字段**。
所以 approve / reject / claim 这类「点一下」的操作，前端要发 `{}`，不要省略 body，
否则收到的是 pydantic 的 `Field required` 而不是有业务含义的错误。

受影响的接口：`/v1/admin/revision/{id}/approve`、`/reject`、`/v1/person/{id}/claim`、
`POST /v1/person`、`PATCH /v1/person/{id}`。

### 入口：怎么进到一个家族

「我加入过哪些族」的唯一真相是 **`user_family`** 表。
`app_user.family_id` 只表示**当前正在看哪个族**——首页、答题自证、编辑鉴权
读的都是这个快照，所以它必须由后端原子切换，端上不许自己算。

一个账号可以**同属父系谱和母系谱**，两边的角色和认领人互不影响
（在 A 族是房长、在 B 族是普通族人，切回来还是原样）。

切族只能走后端 `POST /v1/family/switch`，因为它要同时回填
`app_user` 的 `family_id` / `role` / `claimed_person_id` 三列。
只换端上显示、不换库里快照，结果就是「页面在 A 族、权限按 B 族算」。
端上入口：**首页点族名** → 族列表 → 切换，或「＋ 加入其他家族」回落地页输码。

进族的唯一入口仍是 `pages/landing/landing`，**一页两态**：

| 进来方式 | 页面状态 | 去向 |
|---|---|---|
| 家族群点链接 / 扫小程序码（码在链接里） | 预览态：堂号 + 始迁祖 + 三代脱敏 | 点「进去看看」→ `POST /v1/invite/{code}/accept` → 加入该族并切为当前族 |
| 直接打开小程序（没有码） | 输码态：一个输入框 + 为什么要码 | 输码 → 同一个预览态 |
| 链接已失效（40302） | 退回输码态，把原因写在输入框下 | 用户当场换一个码，而不是撞一堵墙 |

首页（`home`）启动时按**三种状态**分流，这是这一屏最要紧的一段逻辑：

| 后端的状态 | 含义 | 去向 |
|---|---|---|
| 答复了、家族为空 | 确实没入族 | `redirectTo` 落地页输码 |
| 压根没答复 | 网络 / 服务问题 | 提示重试（**不**伪装成"你没入族"） |
| 答复了、有族 | 正常 | 拉树渲染 |

> 这三种状态曾经被 `if (!fid) fid = DEMO_FAMILY_ID` 一起兜成"渲染 1 号族全树"。
> 后果很隐蔽：用户看到一棵**不属于自己的树**、以为已经进族了，
> 去认领却被后端按 `family_id IS NULL` 拒掉，弹出「请先通过族浏览码或邀请码进入某个宗族」。
> 症状在认领页，病根在首页这一句。`smoke_e2e.py` 的【8】段就是这件事的回归。
>
> 另外 `q.familyId`（URL 参数）只在开发期认：家谱里已故先人的全名在树上是公开的，
> 一个能随手拼进链接的 query 不能当门票。

入族的门槛必须留着——**码负责"进入这个族"，答题负责"在这一族里是谁"**，
两个不同的问题，不该混。进族之后各页面不再回头追问"你当初怎么进来的"。

### 身份确认：答题自证（不再等房长逐个批）

房长年纪大、不会操作审批界面；而同一族的码只会分享给族人，冒领罕见。
阻塞的代价（产品没人用）远大于冒领的代价（可清洗的少量脏数据）。
所以主通道改成：**答出父母的姓名，系统反查，直接通过**。

| 接口 | 作用 |
|---|---|
| `GET /v1/auth/identify/quiz` | 出题：4 个问题（关系 / 亲属名 / 本人名 / 另一位家长）+ 族内人数 |
| `POST /v1/auth/identify/verify` | 答题 → 定位 → 自动认领 / 新建本人节点 |
| `POST /v1/admin/claim/{id}/revert` | 房长抽查发现冒领，一键撤销（连编辑授权一起收回） |

`locate()` 的结果有四种，四种都是正常业务分支，不是异常：

| 结果 | 含义 | 去向 |
|---|---|---|
| `matched` | 谱上有你，唯一命中 | 直接认领，授「自己 + 直系上下两代」 |
| `new_member` | 谱上有你父亲、**谱上还没你** | 主路径。新建节点挂到父亲的婚姻单元上 |
| `ambiguous` | 同名多个，或证据不足 | 要求补填另一位家长；不泄漏任何候选 |
| `no_match` | 对不上，或所填是已故先祖 | 模糊反馈 + 兜底通道（请房长人工核实） |

**题目强度取决于数据**，这条反直觉但决定了实现：

| 所填亲属 | 树上显示 | 强度 |
|---|---|---|
| 在世 | `陈*栋` | 强 —— 外人抄不到 |
| 已故 | `陈国栋` | 弱 —— 名字就在屏幕上，退化成读屏题 |

强度会写进 `claim.verify_answers` 留痕，供房长抽查；而「谱里没我、要新建节点」
这条路径遇到弱证据时会追一道门槛：**再答一位家长的名字**。成本很低，
却能把「照着树抄一遍就能建节点」的噪音挡在外面。

三个洞与三个补丁（都在 `services/identify_service.py` 的模块注释里）：

1. 搜索即枚举器 → **限速**（10 次/小时，连续错 5 次冷却）
2. 已故者姓名公开 → **证据强度留痕** + 新建节点追加门槛
3. 无限次尝试 → 限速 + **模糊反馈**（不区分「没这人」和「不是你父亲」）

第 2 条的做法值得说明：不是"防住"，而是"通过但留痕 + 可撤销"。
家谱数据有长期价值，但垃圾数据可清洗，卡死的产品不可救。

#### 两条写入路径

`person.py` 的 `_resolve_write_mode()` 是唯一的判定处：

| 用户状态 | 目标在 `edit_scope` 内？ | 结果 |
|---|---|---|
| 房长及以上 | — | 直接生效（写 `AUTO_MERGED` 修订留痕） |
| 已认领 | 是 | 直接生效（写 `AUTO_MERGED` 修订留痕） |
| 已认领 | 否 | 进待审队列，**不 403 阻塞** |
| 未认领 | — | 拒绝（40301），走答题自证 |

范围外**排队而不是拒绝**，是因为"拒了就不会再有人改"——家谱缺的那一块
会永远空着，那才是真正的损失。而"生效 ≠ 无痕"：所有写入都留 `revision` 行，
房长随时可回滚。

> 写操作统一以 `data.autoMerged`（bool）告诉端上走了哪条路，
> 端上据此说「已生效，树上马上能看到」还是「已提交，等房长确认」。
> 这个字段**必须显式返回**，不能只塞在 `nextHint` 文案里。

**点人操作环**（2026-10-21）：点树上任一节点，绕着这个人浮出六个动作——
**上父/母、下子/女、左配偶、右详情**。布局按心智模型排而不是平均分布，
"给爷爷补父亲"手指往左上就是父。已填的槽位（比如已经有父亲）会自动置灰，
避免重复建出"同名父亲"——家谱里多一个人比少一个人更难收拾。
补录只问一个名字，`gender` / `lineageRole` / `generation` 由关系推出来一起提交：
**媳妇必须记成 3（不是默认的 1）**，否则"世代丁口人数"里会多出一个男丁。

**视图口径**（2026-10-21 定稿）：真实开场是宗祠理事会拿老谱拍照、OCR 转录，
一次导入十几代、200 活在世、500+ 节点。实测 15 代 / 564 人时整幅适配字号只有
0.47px（画布 9528×2136px）。**"一次看清全族"是数学上做不到的，不做。**

- **全族总览 = 静态骨架**：只画 `lineage_role` 1/2 的直系丁口（**不含媳妇**），
  无姓名，只点位 + 「第 N 世 N 人（男 a 女 b）」刻度 + 「15 代 · 200 丁口」汇总。
  丁口口径由服务端算，和理事会手里的老谱对得上。
- **焦点视图 = 以选中者为中心**：上 1 下 1，**点谁谁居中**，再点他的子女就逐代
  往下钻。一屏三代，不需要靠"看全"来定位自己。
- **点一次是"看这里"，再点一次才是"改这里"**：第一次点节点把他设为中心并展开
  他的妻儿，已经是中心的人再点才浮出操作环。
- **夫妻卡片零间距紧贴**：本人与配偶首尾相接成一条卡片行（`spouseGap=0`），
  接缝两侧的圆角由端上切平，视觉上是一个整体。**卡片位置不随子女数量移动**——
  旧实现把配偶放在"她那列"的中心，列被孩子撑宽，妻子被推到 220px 外，看着像两家人。
  子女仍按生母分组（服务端 `group_by_mother` + 边上带 `motherId`），同母成组、
  异母不混排；分组不保证"孩子正对某个母亲"，这是为夫妻紧贴付的代价。
  **离异配偶绝不隐藏**——卡片画虚框 + 标「已离异」，婚姻横梁也是虚线（丧偶不虚框）；
  把母亲从孩子那一屏拿掉，等于让"离婚"在子女视角里变成"没有母亲"。
  `lineage`（我的支系）已退休，虚拟列表这条待办作废。
